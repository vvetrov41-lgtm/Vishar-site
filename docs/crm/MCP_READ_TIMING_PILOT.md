# CRM MCP request timing pilot

Base: `db1d5599486da1ba88899dd2acd60d9280714b23`. Existing plugin uses an authoritative Supabase /auth/v1/user check, dedicated client ID, per-token rate limiter and named GPT Action service binding. Downstream combined GPT Action uses caller bearer token and an explicit named RPC, not the service-role token. This is a two-step network path; neither step is proven redundant. Keep both checks. Existing read retry policy (up to three transient attempts) and write non-retry behavior remain unchanged.

Proposed diagnostic, disabled by default: `MCP_READ_TIMING_DIAGNOSTICS=true` in an explicitly approved isolated environment only. A successful authenticated read with GET/HEAD and readOnlyHint returns fixed Server-Timing fields auth, rate, action, total, and attempts. Action includes service binding, downstream processing, response reading and retry delay; it does not isolate DB time. No raw headers, OAuth details, identifiers, args, response payload, arbitrary tool names, logs, cache or telemetry export. No timings for discovery, unauthorized, rate-limited, failed or write results. Response JSON and existing access checks are unchanged. No config enabled by this PR.

Verify with the existing generated-tool suite, synthetic read retry, denied/expired/missing auth, rate limit, discovery, write and default-off tests, plus Wrangler dry-run. Activation and production release require distinct authorization. Do not weaken membership, RLS, OAuth or grants to enable timing collection. A connector may hide Server-Timing headers: collect via an approved authenticated client in a test environment, not by extracting credentials.

Security checklist for this narrow change: OAuth client/issuer/audience, live user validation, rate limits and bearer propagation inspected at base; named RPC path unchanged. Database grants, active membership and production token/role binding not independently re-audited here; tests protect existing contracts, not proof of new database security. Public intake, payments, calendar, provider routing, storage and communications persistence unchanged and outside scope. No schema or production changes.
