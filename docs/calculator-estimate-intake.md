# Structured optional calculator intake

Public preview commit 323eb549b7ad065a27730f17315e47044eb4aa74 sends a versioned selection, not a binding price, under projectDetails.calculator_estimate. The old Worker ignores this optional field and receives full placement and estimate text in idea. The new Worker verifies selected regions, placements, work and styles against the ordinary validated form, sanitises enum fields, checks the version and independently calculates the amount using the exact public pricing engine. Invalid optional metadata is omitted, never rejects an otherwise valid enquiry. The production database already accepts a bounded JSON object in enquiries.project_details; no DDL or new permissions are necessary. The CRM displays this as an indicative estimate only, not a project finance amount. Staff structured placement edits may replace the estimate; the original text remains in the enquiry.

Source pricing file is copied byte-for-byte from the public preview commit to this separate CRM release branch. A future pricing revision must change rulesVersion and synchronise both deployment branches; mismatched versions are deliberately ignored. Roll out the Worker before the website, then run a staging intake and CRM view check. No production deployment is authorised by this branch.

## CRM operator interface
Current coverage uses calculator_selection; the immutable client snapshot stays under calculator_estimate and is marked calculator_estimate_superseded on changes. The existing authenticated edit RPC retains its artist access and conflict checks. The project page already reads the source enquiry and uses the same component. Neither field writes agreed finance or payment records. Legacy and Kristina enquiries remain supported; no Vladimir rate is applied to them. The database migration must precede CRM UI deployment.
